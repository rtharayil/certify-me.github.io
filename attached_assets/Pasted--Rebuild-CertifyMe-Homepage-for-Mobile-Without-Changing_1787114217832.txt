# Rebuild CertifyMe Homepage for Mobile Without Changing Desktop

## Objective

I want you to **rework the CertifyMe homepage specifically for mobile and tablet UX**, while keeping the existing desktop/laptop version intact.

The current website was designed primarily with a laptop/desktop mindset. The existing responsive implementation technically adapts the page to smaller screens, but the result is **not a good mobile user experience**.

Do NOT simply shrink the desktop page.

Instead, treat this as a **responsive UX redesign of the same homepage**:

* Desktop = preserve the current design, content, structure and visual identity as much as possible.
* Tablet = intelligently adapt the layout.
* Mobile = create a deliberately designed mobile composition using the same underlying content/data.
* Do not remove important information just because mobile has less space.
* Do not create a completely different website or change the business messaging.
* Reuse the existing assets, links, content, components and data wherever possible.

The goal is:

> **One homepage, one content source, two presentation systems: desktop and mobile.**

---

# 1. FIRST: Audit the Existing Homepage

Before changing code, inspect the entire homepage and understand:

1. Every section in the current homepage.
2. The purpose of each section.
3. The hierarchy of information.
4. Which elements are essential.
5. Which elements are secondary.
6. Which elements can be collapsed on mobile.
7. Which elements need to become cards, accordions, horizontal scrolls, tabs or stacked blocks.
8. Which elements are causing horizontal overflow.
9. Which elements have excessive vertical spacing.
10. Which typography becomes too large or too dense on mobile.
11. Which images become too dominant.
12. Which CTA buttons become difficult to use.
13. Which navigation elements are difficult to use.
14. Which tables/data visualizations are unusable on small screens.

Do not start blindly modifying CSS.

First understand the existing page.

---

# 2. IMPORTANT: DO NOT BREAK DESKTOP

This is critical.

The existing laptop/desktop version is the baseline.

Do NOT redesign the desktop page simply because you are improving mobile.

Do NOT:

* change desktop spacing unnecessarily
* change desktop typography unnecessarily
* change desktop section ordering
* replace desktop components unnecessarily
* remove desktop content
* change desktop navigation behaviour unless required for a shared component
* change desktop URLs
* change SEO metadata
* change structured data
* change analytics/tracking
* change existing CTA destinations

The desktop version should continue to look essentially as it does today.

Use responsive breakpoints and/or mobile-specific presentation rules/components where appropriate.

The existing page already includes responsive CSS and an enterprise override stylesheet, so inspect those carefully before adding new styles.

---

# 3. MOBILE SHOULD NOT BE "DESKTOP SHRUNK"

This is the most important design principle.

Do NOT do this:

Desktop:

[IMAGE] [TEXT] [CTA] [CTA]

Mobile:

[IMAGE]
[TINY TEXT]
[TINY BUTTON]
[TINY BUTTON]

Instead, rethink the composition.

For example:

Desktop:

TEXT | VISUAL

Mobile:

TEXT
CTA
CTA
VISUAL

Similarly:

Desktop:

[Card] [Card] [Card]

Mobile:

[Card]
[Card]
[Card]

OR, where appropriate:

[Card] → [horizontal scroll]

OR:

[Section title]
[Most important information]
[View more]

The mobile layout should feel intentionally designed rather than compressed.

# 5. MOBILE TYPOGRAPHY

Do not simply scale every font proportionally.

Create a deliberate mobile typography hierarchy.

Recommended starting point:

### H1

Approximately:

`32–38px`

depending on screen width.

### H2

Approximately:

`26–30px`

### H3

Approximately:

`20–24px`

### Body

Approximately:

`15–17px`

### Small supporting text

Approximately:

`13–14px`

Do not make body text smaller than necessary just to fit more content.

**Readable content is more important than fitting everything above the fold.**

Use responsive `clamp()` values where appropriate rather than dozens of arbitrary breakpoints.

# 7. HERO SECTION — REDESIGN FOR MOBILE

The hero is one of the most important areas to redesign.

Current desktop hero uses:

* headline
* supporting paragraph
* two CTAs
* credential tags
* large visual
* two-column layout

Keep all of that content.

But on mobile use:

### Mobile structure

1. Headline
2. Short supporting description
3. Primary CTA
4. Secondary CTA
5. Hero visual
6. Trust/credential indicators

Do not force the two-column desktop arrangement onto mobile.

The current hero headline is:

"The Digital Credential Infrastructure for Institutions"

and the supporting message explains issuing, managing, verifying and analyzing credentials at scale. Preserve the messaging unless there is a strong UX reason to shorten it visually.

### Mobile hero requirements

* H1 must be comfortably readable.
* Maximum text width should be controlled.
* Buttons should be large enough for touch.
* Primary CTA should be visually dominant.
* Buttons can become full-width or nearly full-width.
* Hero image should not consume the entire first screen.
* Avoid excessive empty space.
* Do not make the user scroll through a huge image before seeing the next meaningful information.

The current credential tags are hidden entirely on screens below 768px.

Instead of simply hiding them, evaluate whether the most important trust signal should remain visible on mobile.

For example:

**Open Badges 3.0 Certified · Enterprise Integrations · G2 Leader**

Could become compact chips, a small trust row, or a single "Open Badges 3.0 Certified" trust indicator.

# 8. CUSTOMER LOGOS

The current customer logos are presented as a horizontal desktop list.

Do not squeeze six logos into a mobile row.

On mobile use one of:

* two-column grid
* compact horizontal carousel
* carefully sized logo strip
* 3 + 3 grid

Prioritize recognition and whitespace.

Do not distort logos.

Do not make logos so small that they become meaningless.

# 10. ALL CARD GRIDS

For every multi-column card/grid section, evaluate it independently.

Desktop:

`3 cards`

Mobile should normally become:

`1 card`

But do NOT automatically stack everything.

Where there are many similar cards, consider:

* horizontal swipe carousel
* accordion
* "featured + view all"
* compact grid
* tabs

Do not make the mobile page unnecessarily long.

The question for every section is:

> "What is the best way for a person holding a phone to consume this information?"

Not:

> "How do I make the desktop grid fit?"

---

# 11. TABLES / DATA-HEAVY SECTIONS

This is especially important.

If the homepage contains comparison tables or data-heavy layouts, **do not simply make the entire table overflow horizontally**.

For mobile, transform tables into:

### Option A — Stacked comparison cards

Example:

**CertifyMe**

Standards
Open Badges 3.0
W3C VC
CLR

Integrations
LMS
API
Enterprise

### Option B — Priority columns

Show only the most important columns initially.

Allow:

**View full comparison →**

### Option C — Horizontal scroll

Only use horizontal scrolling if the table genuinely requires simultaneous column comparison.

If horizontal scrolling is used:

* clearly indicate scrollability
* preserve column headers
* avoid tiny text
* keep first column sticky if useful
* ensure touch scrolling works naturally

Never allow a table to create accidental page-level horizontal scrolling.

---

# 12. LONG CONTENT

The desktop homepage can afford more information.

Mobile cannot.

Do NOT delete content.

Instead use:

* accordions
* expandable sections
* "Read more"
* "View all"
* tabs
* horizontal cards
* progressive disclosure

Important content should be visible.

Secondary detail can be collapsed.

This preserves the same data while improving mobile UX.

---

# 13. SECTION SPACING

The current desktop page has large section spacing designed for large screens.

Mobile should use a tighter vertical rhythm.

As a starting point:

* section padding: approximately 48–72px
* card gaps: approximately 16–20px
* internal card padding: approximately 20–24px
* heading-to-body gap: approximately 12–16px
* body-to-CTA gap: approximately 20–24px

Do not apply these blindly.

Use visual judgment.

The objective is:

**compact but not cramped.**

---

# 14. IMAGES

Every major image must be reviewed for mobile.

For each image determine:

* Is it necessary?
* Is it decorative?
* Does it communicate product functionality?
* Does it become too tall?
* Does it crop badly?
* Does it push important content too far down?
* Should it be displayed after the text?
* Should it become smaller?
* Should it use a different crop?

Do not simply set every image to `width:100%`.

Use appropriate:

* `object-fit`
* `aspect-ratio`
* `max-height`
* responsive sizing
* controlled cropping

Reuse the existing image assets wherever possible.

---

# 15. BUTTONS / CTA UX

Mobile CTAs need to be thumb-friendly.

Minimum target:

approximately 44px touch height.

Avoid:

[Request Demo] [Start Trial]

being squeezed side-by-side on narrow screens.

On mobile prefer:

[ Request a Demo ]

[ Start Free Trial ]

or a deliberate stacked arrangement.

Maintain the existing destinations.

Do not invent new CTA destinations.

The existing hero already uses Request a Demo and Start Free Trial, so preserve these actions.

---

# 16. MOBILE CTA STRATEGY

Do not have ten competing CTA styles.

Establish:

### Secondary

Start Free Trial

Use the same hierarchy consistently.

At appropriate points on the mobile page, consider a sticky bottom CTA:

If implemented:

* respect safe-area insets
* do not cover content
* provide enough bottom padding
* make it dismissible if appropriate

# 20. DO NOT HIDE IMPORTANT CONTENT JUST TO PASS A VISUAL TEST

This is important.

Do not solve mobile problems by doing:

```css
display:none;
```

for major content unless there is a clear UX reason.

For every piece of content hidden on mobile, ask:

> Can this information be represented more efficiently instead?

For example:

Desktop:

6 feature cards

Mobile:

Featured feature card
+
"View all features"

is better than simply deleting five features.

Do not create a breakpoint for every device width.

# 24. TEST FOR THESE SPECIFIC FAILURES

You must actively test and fix:

### Horizontal overflow

There must be no accidental page-level horizontal scroll.

### Text clipping

No heading, button or label should be clipped.

### Tiny text

No important content should require zooming.

### Excessive whitespace

Mobile should not contain huge empty areas inherited from desktop.

### Excessive page length

Avoid unnecessarily stacking dozens of repetitive cards.

### Broken images

Every image must load and remain correctly proportioned.

### Navigation

Menu must be easy to open, understand and close.

### CTA usability

Buttons must be easy to tap.

### Sticky elements

Nothing should cover important content.

### Animation

Reduce/remove animations that make mobile feel slow or distracting.

Respect:

`prefers-reduced-motion`.
